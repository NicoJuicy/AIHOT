# Event overview prompt evaluation

The overview on event pages is generated by `industry/prompts/story-digest.md`. Before changing this prompt, run the current prompt and a candidate side by side on the same events and compare them by hand, rather than judging from impressions of the pages.

## 1. Prepare cases

```bash
node --env-file=.env scripts/eval-story-digests.ts --stories <event id>,<event id> --out .data/story-digest-cases.jsonl
```

The event id is the segment in the event page address `/story/<id>`. The export only reads the database: it doesn't call models or change any event. Reports are chosen by the same rules the site uses when generating overviews, except that reports only mentioning the event in passing, roundups, withdrawn reports and reports not yet public don't count. Events that already have an overview are assembled as "rewrite after correction" (without the previous overview), and events without one as a first draft. Events that can't be found, have been merged, or have no usable reports fail with an error.

The exported file has one event per line and can be reviewed first. To test the incremental update when new reports arrive, change `inputMode` to `incremental` and fill in `story.previousDigest` and `knownArticleIds` (the ids of reports the previous version already covered). You can also write cases by hand; see `industry/story-digest-eval.example.jsonl` (fictional examples) for the format.

## 2. Compare side by side

```bash
node --env-file=.env scripts/eval-story-digests.ts --cases .data/story-digest-cases.jsonl --system my-candidate.md
```

- Each case runs once with the current prompt and once with the candidate: the same model (by default the current model of the "Event overview" step; `--models` picks others) and the same input. The system prompt, input and sampling parameters sent to the model are exactly the same as when the site generates overviews.
- The candidate file is written the same way as those in `industry/prompts/`: `{{siteName}}` is replaced with the site name and `{{> file name}}` includes shared rules; missing values are an error. If the candidate renders exactly the same as the current prompt, the run is refused. Without `--system`, only the current prompt runs.
- Before starting it prints the number of calls (cases × models × prompts), and if that exceeds `--max-calls` (default 18) nothing is sent. Each call is recorded and counted against the budget like the site's other model requests; rerunning unchanged reuses results already received at no further cost, so when you revise the candidate and run again, the current-prompt half costs nothing.

Results are written to `.data/eval/` (changeable with `--out-dir`), as one JSON file and one Markdown file: headlines and overviews of both sides next to each other, with each call's token usage and record ID, and the reason for any failed call.

## 3. What to look at by hand

There is no reliable automatic score, and this tool doesn't let a model grade a model. Go through each one:

- Does it first state the core change and the current conclusion, rather than retelling the timeline below by date?
- Is there empty promotional tone or boilerplate?
- Are limits such as conditions, who it applies to, pricing and quotas, and regions still tied to the right subject?
- Is there anything not in the reports and factual evidence, any commentary on the reports themselves ("the report didn't disclose…"), or writing instructions leaking into the text?
- When rewriting after a correction, have outdated old statements been removed?

## 4. After changing the prompt

A new prompt version doesn't rewrite existing overviews by itself. An event's overview is only regenerated when its reports change, and with new reports the old overview is the previous version for an incremental rewrite, so a new prompt takes effect gradually with new reports and never causes a burst of model calls.

To rewrite certain events with the new prompt right away, call `rewriteStoryDigest` from the repository root (one model call per event, recorded in the admin audit log):

```bash
node --env-file=.env --input-type=module -e '
const { rewriteStoryDigest } = await import("@aihot/backend/events/corrections");
const { sql } = await import("@aihot/backend/db");
const [s] = await sql`SELECT id FROM stories WHERE public_id = ${"<event id>"}`;
if (!s) throw new Error("No event with this id");
console.log(await rewriteStoryDigest(s.id, "Overview prompt updated", "ops-script"));
await sql.end();'
```
