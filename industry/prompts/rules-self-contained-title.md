
[Self-contained title rules: let readers know "what this is about and who it concerns" without opening it]

1. The title must name the core subject: model name / product name / company name / project name.
2. When the original title already names the subject clearly: translate a non-English title into English and keep an English title's meaning; do not rewrite for the sake of rewriting.
3. When the original title is only a version number / codename / an uninformative teaser (such as "v2.1.159", "Small is a feature", "Day 1", "Big news"), add the subject to the title using the [Source] and the body. Example: original title "v2.1.159" + source "Claude Code: GitHub Releases" → "Claude Code v2.1.159 released".
4. Add a subject only with names that actually appear in the [Source] or the body. When neither the body nor the source names a specific model, fall back to a general term (such as "open multimodal model"); never invent a specific model / version / number from "industry common knowledge".
5. The [article type and core action] expressed by the original title is a hard boundary: for explanation, analysis, tutorial or review titles such as How / Why / Guide / Analysis / Review / Benchmark, the title must keep that type; do not rewrite it as "releases / launches / goes live / open-sources" just because the body discusses an existing model, product or new data. Only when the original title explicitly announces a release, launch, going live or open-sourcing may the title use that action. Keeping the article type does not mean dropping the subject: still add the company, product or project name that the body or source clearly gives, per rules 1–4.
   Example: original title "How GPT-5.6 fuses frontier intelligence with frontier efficiency" → "How GPT-5.6 balances frontier intelligence and efficiency", not "OpenAI releases GPT-5.6".
   Example: original title "How to build interactive experiences with canvases" + the source and body clearly concern GitHub Copilot → "How to build interactive experiences with canvases in GitHub Copilot", not the subject-less "How to build interactive experiences with canvases".
6. Keep this item's action apart from an old release in the background: when the source describes the release as past ("At DevDay, we introduced …", "Last week we launched …") and this item explains usage, gives a demo or promotes it again, the title says introduce, demo or explain, and presents the release as earlier; it must not say "launches / releases / goes live", or readers will take it as today's news. Only when the source makes clear that a capability opens or is added now, use the matching action for that capability.
   Example: body "At DevDay, we introduced ChatGPT Space … See how it works below" → "OpenAI demos team collaboration in ChatGPT Space, introduced at DevDay", not "OpenAI launches ChatGPT Space at DevDay".
